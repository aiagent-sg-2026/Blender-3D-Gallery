# Learning roadmap and future Skill candidates

<!-- KB-SUMMARY-START -->
Learn by producing and independently checking small artifacts: coordinate/mesh ownership -> topology/modifiers -> UV/PBR -> reproducible bpy -> modular architecture -> skinning/animation -> glTF/runtime -> evidence-based delivery. Each stage needs an observable exercise, not only a tutorial or extension install. Revisit prior stages when a probe exposes an incorrect assumption. Candidate Skill IDs remain proposals: blender:python-modeling, blender:architecture-generator, blender:character-rig-animation, blender:glb-export, blender:asset-pipeline and blender:extension-audit. They are not registered or enabled by a knowledge update. Reuse an existing applicable Skill before creating another. The current native calibration covers a small static/animated object workflow; character deformation, five extension operations and physical-device behavior remain outside its coverage. Keep dated tool-version knowledge separate from durable procedures.
<!-- KB-SUMMARY-END -->

| Stage | Exercise | Evidence to retain |
| --- | --- | --- |
| Coordinates/ownership | Create an asymmetric object and linked/independent copies | World bounds, data sharing and export axes |
| Topology/modifiers | Make a parameterized opening and inspect an evaluated mesh | Topology contract, solver/settings and resulting geometry |
| UV/PBR | Map a labelled package and numerical material channels | Distortion/density review, decoded images and exported appearance |
| Automation | Run a bounded build from clean background Blender | Inputs, versions, output assertions and nonzero failure behavior |
| Architecture | Assemble repeatable bays and a moving door | Connectors, end conditions, usable clearance and controller/camera checks |
| Character | Skin a joint and create named action slots/clips | Rest/posed comparison, weights, export and runtime playback |
| Runtime | Compare shared storage, batching and instancing | Target-engine draw calls, frame time, culling and visual regression |
| Delivery | Reopen/edit/re-export a source and validate the consumer | Exact artifact identities and qualified acceptance |

The [Blender scripting introduction](https://docs.blender.org/manual/id/5.1/advanced/scripting/introduction.html) is a starting point; this exercise sequence is a proposed learning design. It is not a claim that every stage has been completed by this research.

Keep future Skill work separate from knowledge curation. A new Skill needs an actual repeated procedure, a defined trigger, current instructions and its own verification. Installing an extension does not satisfy those requirements.
